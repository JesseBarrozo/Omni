# Changelog

## Unreleased

- Antigravity feasibility : `agy --help` et la documentation officielle ne fournissent aucun override de HOME/settings/hooks. Le catalogue OAuth réel renvoie 13 modèles avec le HOME connecté, mais échoue avec un HOME isolé sans clé API. Omni conserve le refus sûr si les hooks globaux rendent le mode headless invérifiable; aucun fichier de configuration ni credential utilisateur n’a été modifié ou copié.

- Rapport Auto : `usage report` inclut désormais les résultats `routing.result` filtrés et la latence moyenne réellement mesurée pour les exécutions Auto; les mesures absentes ne sont pas extrapolées.

- OpenAI usage capture : les réponses complètes `response.completed` de l’API Responses enregistrent les compteurs officiels input/output/reasoning/cache dans `usage.updated` pour les chemins API et OAuth; aucune estimation de coût n’est créée. Validé avec le SDK OpenAI réel contre un SSE HTTP loopback, sans appel fournisseur.

- Usage Anthropic/Gemini : les SDK officiels exposent les compteurs de la réponse finale et les écrivent dans `usage.updated`; les dimensions absentes restent absentes. Le rapport agrège chaque compteur indépendamment et indique `null` quand aucun échantillon ne le fournit. Contrats SDK validés via les serveurs HTTP loopback existants, sans fournisseur externe.

- Usage report CLI : `omni usage report --project PATH_OR_ID` et `--conversation ID` résument les coûts USD et tokens réellement persistés, avec sortie texte ou `--json`; les mesures absentes ne sont pas estimées. Le calcul CLI est testé sur l’historique SQLite.

- OpenCode usage events : Omni now consumes the official `session.next.step.ended` event and persists validated USD cost plus input/output/reasoning/cache token counts as `usage.updated`, deduplicated per assistant message. Contract-tested against the SDK event schema; a live model turn remains untested.

- Auto OpenCode budget metadata : OpenCode model catalog input prices now flow into Auto in the documented USD-per-million-token unit. For context-tier catalogs Omni uses the maximum input price, so efficiency ranking and configured input ceilings are conservative; absent or invalid prices remain unknown and are filtered by a configured ceiling.

- Auto capability profiles : OpenCode model catalog now preserves tool-call support and classifies providers as local only when the official provider registry exposes a loopback API URL. Auto filters models explicitly lacking tool calls, `local-first` ranks explicitly local models before preferred remote providers, `privacy` enforces an approved harness, and unsupported profile names fail validation. Model generation and tool calls remain untested for OpenCode.

- Auto Router OpenCode : le routeur déterministe consulte le catalogue réel du serveur OpenCode local et peut choisir ses modèles pour les tâches avec outils; les autres fournisseurs peuvent être exclus explicitement sans interroger leurs credentials ou APIs. `omni auto plan` affiche les candidats, exclusions, critères et secours sans créer de conversation ni lancer de modèle. Le catalogue et le choix réel sont validés par un test opt-in contre le CLI/serveur OpenCode; aucune génération de modèle n’est incluse.

- OpenCode Harness Swap : `omni swap --conversation ID --harness opencode` now uses the existing safe-boundary checkpoint service; it records a persistent resume summary and injects it only once, with consumption tracked in the canonical event store. The official local-server CLI swap and SQLite restart/resume test pass without a model call. A full file-writing Harness A → OpenCode → Harness A model run remains untested.

- OpenCode Harness (partially validated): official `@opencode-ai/sdk` v2 client and local CLI server, loopback binding with an ephemeral Basic password, isolated child environment, real model catalog, persisted session references, restart resume, interrupt, checkpoints, streamed event normalization, and Omni permission prompts. The installed server’s OpenAPI schema confirms its `decision` field while the SDK generates `reply`; Omni applies a schema-checked fetch bridge. Real session lifecycle and permission create/reject API tests pass without model calls. No authenticated generation, actual tool execution, or interactive model-originated permission event has been run. OpenCode can now participate in deterministic Auto selection for tool-capable tasks; MCP and strict privacy constraints remain. The full model/tool roundtrip is still untested.

- Harness test fixture : `MockHarnessAdapter` a été retiré de `src` et du package publié; il vit désormais sous `test-fixtures/` et un test vérifie les exports publics. Les vrais adapters restent inchangés.

- Gemini Developer API : provider Google distinct d’Antigravity via le SDK officiel `@google/genai` 2.31.0 (Apache-2.0), catalogue paginé filtré sur `generateContent`, streaming, interruption, routage Auto, clé dédiée au trousseau et aucune relance HTTP automatique des générations. Validation SDK loopback; aucune clé réelle ou API distante utilisée.

- Anthropic API : ajout distinct de Claude Code, via le SDK officiel `@anthropic-ai/sdk` 1.3.0 (Apache-2.0), pagination de `models.list()`, streaming Messages API et credentials dédiés du trousseau. Le SDK a passé un parcours contrat complet contre un serveur HTTP local; aucune clé réelle ni requête live utilisée.

- OpenRouter : nouveau provider via le SDK officiel `openai` et l’endpoint OpenAI-compatible Chat Completions documenté par OpenRouter. Le catalogue et le chat streamé sont intégrés aux commandes `providers refresh`, `models list`, `chat` et `resume`; clé dédiée au trousseau système ou variable `OPENROUTER_API_KEY`, erreurs expurgées. Test SDK HTTP local réussi; aucun appel live ni test de clé OpenRouter effectué.

- Codex app-server : test live OAuth de `item/commandExecution/requestApproval` avec acceptation ponctuelle puis refus. Une commande shell locale approuvée écrit son marqueur une fois; la commande jumelle refusée ne s’exécute pas. Le profil supplémentaire `item/permissions/requestApproval` n’a pas été sollicité par le runtime lors de l’essai loopback; il reste à valider lorsqu’un scénario sûr le déclenchera.

- MCP distant Streamable HTTP : transport du SDK TypeScript officiel dans le registre Omni, URL HTTPS (HTTP loopback seulement), en-têtes alimentés uniquement par variables d’environnement, migration SQLite v5, commandes CLI et configuration native Codex/Claude. Aucun appel OpenAI par clé.

- Codex harness MCP : intégration au mécanisme natif `mcp_servers` de l’app-server officiel; consentement avant lancement de chaque serveur et requête d’approbation à usage unique avant chaque appel, arguments/résultats retirés des événements et variables limitées à `--env-names`. Parcours live OAuth Codex + SDK MCP local exécuté une seule fois. La version testée ne fournit pas le nom de l’outil dans la demande d’approbation; l’interface demande un accord serveur/appel générique. Auto accepte `--require-mcp SERVER[,SERVER]`, filtre déterministement les capacités stdio par harness, s’arrête sans fallback après refus de permission et conserve le fallback si un harness autorisé est indisponible avant le début du tour. Un fallback Codex indisponible → Claude OAuth avec le même outil MCP est passé en PTY. Le test live Codex → Claude → Codex avec serveur SDK MCP, checkpoints, permissions et marqueur non répété est passé. Le CLI complet `omni run --auto --require-mcp` a aussi été validé en PTY avec Codex OAuth : démarrage/apel approuvés, marqueur unique; un second run refusé s’est arrêté avant le tour sans fallback.
- Claude harness MCP : transmission des serveurs stdio du registre Omni au SDK Agent officiel, approbation interactive avant démarrage de chaque serveur puis avant chaque outil, et omission des arguments/résultats MCP des événements canoniques. Test réel Claude OAuth → serveur MCP SDK local → outil exécuté une seule fois réussi; aucune clé OpenAI utilisée.
